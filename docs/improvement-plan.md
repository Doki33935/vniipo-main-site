## Подход к развитию

Не переносить административную логику в тему. Не выделять дополнительные сервисы без сценария, который не решается текущим контуром. Конференционный плагин сначала покрыть сценариями интеграции и только затем дробить на модули.

При обновлении исходного Conference Service сравнивать версии, проверять API и миграции схемы, обновлять контрольные суммы отдельным коммитом. Новая тема должна продолжать использовать его функции определения текущей конференции и доступности регистрации.

Для каждого релиза фиксировать завершённые требования, изменения данных, результаты проверок, ограничения и последовательность отката. Успешный CI не заменяет проверку реальных данных и редакторскую приёмку.
