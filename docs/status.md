# Статус версии 0.3.0

Дата: 27 октября 2026 года. Выполнены иерархия брендинга, добавление информационных блоков через CMS и синхронизация опубликованных материалов oren.vniipo.ru.

## Реализовано

- В шапке, главном заголовке, подвале и названии сайта сначала ФГБУ ВНИИПО МЧС России, затем Оренбургский филиал. Оформление на основе vniipo.ru сохранено.
- Редакторские информационные блоки: текст, изображения, файлы, таблицы, области главной, боковая колонка, выбор страницы, порядок, публикация/черновик, повторная вставка через Gutenberg и shortcode.
- Получены все 99 обнаруженных новостей с текстами и датами, 34 информационные страницы, блок «О филиале» и 129 локальных изображений. Структура расширена до 73 страниц. Источники и ограничения — source-sync.md.
- На локальном стенде импортированы 134 материала: созданы 99 новостей и один блок, заполнены 34 страницы. Изображения новостей добавлены в медиабиблиотеку.
- Повторяемый ручной импорт с предварительным планом, защитой редакторских изменений и обработкой порциями в админке. Активация плагина ничего не импортирует.
- Закрытый предпросмотр показывает снимок без наполнения рабочей БД. Подготовлен обновлённый комплект трёх ZIP для действующего конференционного WordPress.
- Обновлены карта разделов, требования, архитектура, планы развития и инструкции редактору.

## Проверки

Проверки выполнены на отдельном локальном стенде: WordPress 7.0.2, PHP 8.3.36, MariaDB 11.4.10, WP-CLI 2.12.0. Рабочий хостинг и oren.vniipo.ru не изменялись.

- npm run check: 73 страницы, шесть пунктов меню, четыре внутренних 301, целостность 29 зафиксированных файлов конференционного проекта, 134 source UID, даты новостей и SHA-256 129 изображений. Синтаксис JavaScript и гигиена исходников проверены.
- PHP: синтаксис 30 файлов без ошибок.
- Интеграция WordPress: повторный scaffold, сохранение контента и главной, конференционный контракт; повторный импорт без изменений/дублей, dry run без записи, конфликт при редакторской правке, сохранение иерархии, порядок/публикация/привязка блоков, shortcode и Gutenberg.
- 86 HTTP-проверок основного сайта, 89 проверок закрытого предпросмотра и 37 проверок перенесённого содержимого — всего 212. Включены все разделы, поиск и пагинация, 404/301, архив и карточка конференции, регистрация/вход, опубликованные материалы и изображения.
- Предпросмотр проверен со старой публичной темой и неактивным core: гость перенаправляется на вход, редактор получает 403, администратор видит новый сайт, POST/PUT/DELETE получают 405. Настройки темы/главной и количество записей, метаданных и заявок сохранены.
- В браузере проверены ширины 1440 и 390 px, порядок названий, реальные новости, меню и Escape, таблица руководства без горизонтального переполнения страницы. Изображения результата сохранены в игнорируемом artifacts.
- В реальном редакторе WordPress проверено сохранение области, конкретной страницы и порядка временного блока. Временные материалы и тестовые сессии удалены. На финальном проверочном прогоне PHP debug.log пуст.

GitHub Actions настроен на эти проверки. Первый запуск версии 0.1.0 был заблокирован billing/spending limit аккаунта до выполнения шагов; успешный удалённый CI не заявляется. Docker ранее завершался ошибкой Inference manager, поэтому локальные проверки выполнялись на portable PHP/MariaDB. Во время финальных проверок внешние фоновые запросы WordPress отключены только в игнорируемой локальной конфигурации.

## Границы готовности

Синхронизация применена локально и поставляется в репозитории/пакете. На удалённый хостинг пакет ещё не устанавливался. Для показа использовать hosting-preview.md, не переключая публичную главную и не импортируя материалы в рабочую конференционную БД ради просмотра.

Перед официальным запуском требуется редакторская проверка перенесённых материалов, подтверждение расхождения email, адресов и дат доверенности в источнике, наполнение отсутствующих разделов. PDF/DOCX и дополнительные фотогалереи пока остаются ссылками на оригиналы. Полные переводы, фотослайдер, подписка, карта и миграция рабочих конференций/заявок остаются следующими этапами. Предпросмотр предназначен для показа; полноценное редактирование и проверка форм выполняются на staging.
