# Статус версии 0.4.0

Дата: 28 октября 2026 года. Технические возможности сайта дополнены по ТЗ. Полная публикация официального контента и перенос рабочего портала требуют сведений от ответственных; незаполненные разделы по решению заказчика подготовлены для последующего наполнения.

## Реализовано

- Сохранены оформление на основе vniipo.ru, иерархия наименований и единый конференционный сервис.
- Реестр содержит 74 страницы. Из источника перенесены 99 новостей, 34 страницы, блок «О филиале» и 129 изображений. Ещё пять разделов заполнены производными материалами из того же источника: устав, образовательная лицензия, схема управления, цели и история. Всего 139 материалов и 39 заполненных страниц.
- Каталог документов: разделы, фильтр, номер, дата, редакция, файл из медиабиблиотеки, официальный источник и ревизии метаданных.
- Фотоальбомы и фотоархив, ручной слайдер с тремя изображениями полигона, кнопками и стрелками клавиатуры. Без JavaScript остаётся список фотографий; автоматического движения нет. Видеоматериалы добавляются штатными блоками WordPress.
- Информационный и презентационный шаблоны страниц. Сохранены редактируемые информационные блоки.
- Единые настройки подтверждённых контактов, карты и официальных соцсетей. Пустые поля не создают вымышленные данные.
- Три языка: русский, английский и традиционный китайский. Подготовлены 96 переводов сообщений интерфейса и 16 черновиков восьми основных страниц; языковые URL, переключатель и hreflang проверены. Полные переводы официальных материалов и конференционного интерфейса не заявляются.
- Точные ссылки на обращения и символику взяты из сохранённого меню официального vniipo.ru. Прямое повторное получение этих страниц 28 октября завершалось TLS timeout; их доступность перед запуском проверяет ответственная команда.
- Подготовлен документ для составителя ТЗ: 24 вопроса на пяти страницах с основаниями и полями ответов. Вёрстка проверена экспортом Microsoft Word и просмотром всех PNG; LibreOffice в Windows runtime отсутствует.
- Подписка и Яндекс Директ отложены по прямому ответу заказчика.

## Проверки

Локальный стенд: WordPress 7.0.2, PHP 8.3.36, MariaDB 11.4.10, WP-CLI 2.12.0; многоязычная проверка с официальным Polylang 3.9.1. Рабочие сайты не изменялись.

- npm run check: 74 страницы, шесть пунктов меню, четыре внутренних 301, неизменность 29 зафиксированных конференционных файлов, 139 source UID и SHA-256 129 изображений. Проверены переводные сообщения и параметры подстановки.
- PHP: синтаксис 37 файлов без ошибок; синтаксис JavaScript и PowerShell проверен.
- Интеграция WordPress: повторяемость scaffold и импорта, защита редакторских правок, отсутствие дублей, сохранение иерархии и конференционного контракта.
- Отдельно проверены публикация, порядок и привязка блоков, shortcode, Gutenberg, документы, даты, ревизии метаданных, nonce, очистка настроек и фотоальбомы.
- 87 HTTP-проверок основного сайта, 90 закрытого предпросмотра, 42 перенесённого содержимого и четыре языковых/презентационных проверки — всего 223.
- Закрытый просмотр проверен со старой публичной темой и неактивным core, включая гостя/редактора/администратора, HEAD, отказ POST/PUT/DELETE, поиск, пагинацию и сохранение настроек, записей, метаданных и заявок.
- Браузер: английский интерфейс, традиционный китайский при ширине 390 px без переполнения, ручное переключение галереи мышью и клавиатурой. Снимки находятся в игнорируемом artifacts.
- Один повторный локальный прогон предпросмотра прервался по таймауту во время параллельной проверки документа; последующий полный прогон всех 90 запросов прошёл успешно.
- Переводы, временно опубликованные только для QA, возвращены в черновики. Тестовые публикации и сессии удалены. На итоговом прогоне PHP debug.log пуст.

GitHub Actions дополнен проверками редакторских функций и отдельной установкой проверенной языковой зависимости. Успешный удалённый CI не заявляется: ранее запуск блокировался billing/spending limit аккаунта. Локальный Docker ранее завершался ошибкой Inference manager; использовались portable PHP/MariaDB. Базовые версии компонентов не обновлялись без проверки.

## Что требуется для закрытия приёмки

Подробная матрица — acceptance.md. Открытые вопросы — specification-questions.json и DOCX в deliverables.

Отсутствуют подтверждённые контакты/карта/соцсети и данные о хостинге; не предоставлены материалы виртуальной экскурсии, лаборатории, сертификации и филиальные документы по обращениям и коррупции. Требуются редакторская вычитка перенесённого контента, согласование состава каталога и переводов, доступ к staging и план миграции актуальных конференций/заявок. Все эти вопросы включены в документ для составителя ТЗ.

Для первого показа на работающем хостинге использовать только пакет dist/preview по hosting-preview.md. Полноценные языки и редактирование настраиваются на новом сайте или отдельном staging по multilingual.md. На удалённый хостинг текущая версия ещё не устанавливалась.
