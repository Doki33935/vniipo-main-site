## Подтверждённое устройство

Тема `fyremezzonine-wp-theme` отвечает за представление: конференционную главную, архив и отдельную конференцию, общие страницы, стили и скрипт эффектов. `functions.php` содержит функции представления, чтения метаданных, дат, площадок, карт и партнёров. Эти функции нужны шаблонам конференций и поэтому сохраняются через наследование темы.

Плагин `fyremezzonine-conference-manager` регистрирует `conference`, поля, роли и права, редакторские маршруты, формы участия и партнёрства, списки и выгрузки, жизненный цикл и журнал. Код большого плагина находится в одном файле; он не декомпозируется в этой итерации.

| Объект | Хранилище или API | Значение для интеграции |
| --- | --- | --- |
| Конференции | `wp_posts`, `post_type=conference` | Сохранить ID либо полную таблицу соответствия |
| Поля конференций | `wp_postmeta`, `_conference_*` | Сохранить даты, дедлайны, площадки, темы, секции, изображения и ссылки |
| Участники | `{prefix}conference_registrations` | Отдельная таблица, не переносить как обычные записи |
| Партнёрские заявки | `{prefix}conference_partner_requests` | Переносить с привязкой к конференциям |
| Журнал | `{prefix}conference_activity_log` | Сохранять связи и хронологию |
| Партнёры | option `fyremezzonine_partner_catalog` | Отдельный общий каталог |
| Пользователи | `users`, `usermeta` | Сверять роли, права, назначение секций; не дублировать ID вслепую |
| Страница регистрации | option `fyremezzonine_registration_page_id` | Плагин умеет создавать и восстанавливать её |
| Контент и настройки | options, theme_mods, uploads | Инвентаризация вне Git |

В документации прежнего проекта жизненный цикл описан как ручное завершение текущей конференции с передачей следующей опубликованной записи. Нельзя заменить это сортировкой по ближайшей дате. Регистрация ограничена текущей конференцией и дедлайном. Основной сайт выводит ссылки на события, а решение об открытой регистрации оставляет плагину.

Сохранены shortcodes `conference_submission_form`, `conference_registration_form`, `conference_partner_request_form`, `conference_registrations_archive`, `conference_operational_summary`, `conference_partner_requests_archive`, `conference_partnership_manager`.

## Что переиспользуется

Перенесены только исходники устанавливаемой темы, плагина и необходимых им assets. Существующие шаблоны `single-conference.php` и `archive-conference.php` наследуются дочерней темой. Стили родителя включаются в контексте конференций и конференционных форм, чтобы не менять оформление основного сайта.

Сохранены `/conferences/`, `/registration/`, `/partnership/`, `/editor/login/`, `/editor/conferences/`, `/editor/registrations/`, `/editor/summary/`, `/editor/partnership/`. Новый основной сайт использует собственную главную; прежняя конференционная главная больше не владеет `/`.

## Что не переносится автоматически

Дампы БД, `.env`, пользователи, реальные заявки, backups, скриншоты VM, архивы презентаций и отдельный `NFMP-worktree` не являются исходниками нового сайта. Существующая инфраструктура Astra Linux и конфигурация VM не считаются автоматически пригодными для нового сайта: новый код рассчитан на PHP 8.3, а старый проект сохранял совместимость с PHP 7.3.

В плагине есть обновление схемы, включая удаление устаревших полей email verification. Поэтому активация на импортированной рабочей БД допускается только после резервной копии и проверки миграции на копии. Имеющиеся константы сроков хранения IP, персональных данных и журналов — существующая реализация; они не означают согласованные сроки нового сайта.

Не заявляется повторный полный аудит безопасности прежнего плагина: он требует отдельного этапа и проверки прав, форм, выгрузок, загрузок, антиспама и обработки персональных данных.
