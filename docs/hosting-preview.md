# Просмотр нового сайта на хостинге конференций

Для первого показа администраторам подготовлен плагин **VNIIPO Private Preview**. Он работает внутри существующего WordPress: активная тема конференций сохраняется, а VNIIPO Main применяется только к авторизованному запросу по адресу `/vniipo-preview/`. Новые разделы берутся из JSON-структуры и отображаются без создания страниц в рабочей БД.

Для этой задачи не нужны новый домен, отдельная БД, Docker, импорт дампа или перевод WordPress в Multisite. Реальную установку на удалённом хостинге в этой итерации не выполняли: доступ и текущая версия PHP на нём пока не подтверждены.

## Предварительные условия

- Есть администратор WordPress с правом `manage_options` и возможностью устанавливать темы/плагины.
- WordPress 6.9 или новее. Новая тема требует PHP 8.3. Версию проверить в «Инструменты → Здоровье сайта → Информация → Сервер»; CLI-версия PHP может отличаться от версии веб-сайта.
- На сайте уже установлена тема с каталогом `fyremezzonine-wp-theme` и активен Conference Manager. Их работающую версию не заменять архивами из нового проекта ради просмотра.
- Пакет core 0.4.0 содержит 129 изображений источника и занимает около 14 МБ. Проверить лимит загрузки WordPress/PHP; если он ниже размера ZIP, передать файлы через файловый менеджер хостинга или SFTP. Пределы PHP публичного сайта автоматически не меняются.
- Перед установкой есть обычная резервная копия хостинга. Из page cache, CDN и серверного кэша исключён `/vniipo-preview/*`; плагин дополнительно ставит запрет кэширования и индексации.

Если на хостинге PHP 7.3, 7.4, 8.1 или 8.2, текущая новая тема там не запускается. Сам плагин предпросмотра выдаст понятное сообщение вместо загрузки несовместимой темы. Не менять PHP публичного сайта ради показа без отдельной проверки конференционного сервиса. В таком случае нужен staging с PHP 8.3 либо отдельная задача совместимости.

## Подготовка пакета

Готовый передаваемый комплект после сборки: `dist/hosting/vniipo-hosting-preview-0.4.0.zip`. Сначала распакуйте его на компьютере и откройте `START-HERE.html`. Общий ZIP содержит три установочных архива; загружать его целиком как плагин WordPress нельзя. Краткий текстовый порядок — `READ-ME-FIRST.txt`, параметры комплекта — `MANIFEST.json`. У общего архива есть отдельный файл SHA-256.

В репозитории:

```powershell
npm run check
./scripts/build-preview.ps1
```

В `dist/preview` появятся:

| Файл | Что устанавливается | Действие в WordPress |
| --- | --- | --- |
| `vniipo-main.zip` | Новая дочерняя тема | Установить, оставить неактивной |
| `vniipo-core.zip` | Структура и материалы основного сайта | Установить, оставить неактивным для этого сценария |
| `vniipo-preview.zip` | Закрытый просмотр | Установить и активировать |
| `SHA256SUMS.txt` | Контрольные суммы ZIP | Проверить при передаче |
| `INSTALL.md` | Эта инструкция | Передать ответственному администратору |
| `START-HERE.html` | Краткая инструкция с таблицей состояний | Открыть браузером после распаковки |
| `READ-ME-FIRST.txt` | Быстрый порядок действий | Прочитать перед установкой |
| `MANIFEST.json` | Версия, требования, хеши и состояния компонентов | Сверить комплект |

Пакет не содержит WordPress core, Conference Manager, родительскую тему, пользователей, заявки, SQL или секреты. Это позволяет добавить просмотр, сохраняя установленную рабочую версию конференционного сервиса. Если VNIIPO Core уже используется другим функционалом, не деактивировать его; плагин умеет работать и с уже активным core.

## Установка только через админку

1. Зайти в существующий `/wp-admin/` своей административной учётной записью.
2. Открыть «Внешний вид → Темы → Добавить тему → Загрузить тему», выбрать `vniipo-main.zip`. После установки не нажимать «Активировать».
3. Открыть «Плагины → Добавить плагин → Загрузить плагин», установить `vniipo-core.zip` и оставить неактивным, если он ещё не используется.
4. Аналогично установить `vniipo-preview.zip` и активировать только этот новый плагин.
5. Открыть «Инструменты → Предпросмотр ВНИИПО → Открыть новый сайт».
6. Передать ссылку из этой страницы другим администраторам. Каждый входит в WordPress под своей учётной записью. Секретные токены или общая публичная ссылка доступа не нужны.
7. Проверить обычную главную в приватном окне браузера: она должна остаться конференционной. Затем проверить предпросмотр в административной сессии.

Адрес формируется от фактического `home_url` WordPress. Например, если портал установлен на `https://orenvniipo.online/`, ссылка будет `https://orenvniipo.online/vniipo-preview/`. При установке WordPress в подкаталоге его базовый путь сохраняется автоматически.

Не запускать `scripts/bootstrap.sh`, `scripts/dev.ps1`, импорт БД или `wp vniipo scaffold --set-front-page` на рабочем портале ради показа. Обновление постоянных ссылок для нового просмотра не требуется: используется уже существующая маршрутизация WordPress.

## Что увидят администраторы

Новая главная, все 74 раздела структуры, поиск, новые общие шапка и подвал, архив и карточки уже опубликованных конференций. В 0.4.0 поставляется снимок oren.vniipo.ru: 34 исходные и пять производных информационных страниц, 99 новостей, блок «О филиале» и 129 изображений. При отсутствии импортированного контента страницы и карточки новостей читаются из снимка; карточки ведут на оригиналы. Если импорт уже выполнен, используются записи WordPress и редакторские блоки. Поиск работает по опубликованной БД и не индексирует JSON-снимок. Остальные незаполненные разделы показывают честные пустые состояния. Подробнее — `source-sync.md`.

Все страницы просмотра содержат заметную полосу «Закрытый предпросмотр». Публичные формы и кабинеты в пространстве просмотра заменены информационным экраном, POST/PUT/DELETE отклоняются до обработчиков форм. Действующие адреса регистрации и кабинетов вне `/vniipo-preview/` продолжают обслуживаться прежним сервисом.

Плагин не вызывает `switch_theme`, не меняет главную и не создаёт контент. VNIIPO Core подгружается только внутри разрешённого просмотра, если он неактивен. Это не отдельная база и не изолированная песочница для сторонних плагинов: обычные механизмы авторизации, фоновые задачи и установленный WordPress продолжают жить в существующем окружении. Для редактирования структуры, тестирования отправки заявок и обновлений схемы нужен отдельный staging.

## Приёмка на хостинге

1. Гость по адресу просмотра попадает на вход WordPress.
2. Редактор без `manage_options` получает 403.
3. Администратор видит новую тему только по `/vniipo-preview/`.
4. Обычная главная и конференции у гостей и администраторов сохраняют прежнее оформление.
5. Проверить разделы, поиск, архив и карточку конференции, меню на телефоне.
6. Проверить `Cache-Control`, `X-Robots-Tag` и исключение пути из внешнего кэша.
7. Убедиться, что настройки активной темы, главной, количество страниц и заявок остались прежними.

## Отключение

Деактивировать VNIIPO Private Preview. После этого специальный просмотр больше не обслуживается плагином. Если новые тема и VNIIPO Core использовались только для показа и остаются неактивными, их можно позднее убрать штатными средствами WordPress. Восстанавливать БД из-за выключения просмотра не требуется.

## Следующий шаг после согласования

Для полноценного редактирования и миграции выбрать staging на том же хостинге с отдельной БД и PHP 8.3. Там можно активировать новую тему, создать структуру, перенести копию конференций и проверить формы. Переключение публичной главной выполняется после приёмки по `conference-integration.md`.

Для первого показа устанавливаются только три архива из `dist/preview`. Polylang и сценарий подготовки языков предназначены для нового сайта или отдельного staging; на работающем портале ради просмотра их не устанавливают. В предпросмотре без Polylang показывается русская версия.
